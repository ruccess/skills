# korean-docs 가독성과 한국어 품질 강화 설계

## 목표

`korean-docs`가 문법 오류를 고치는 수준을 넘어 긴 문서를 사람이 빠르게 훑고 정확히 이해하도록 만든다.
문서의 정보 구조, 문단, 줄바꿈, 관계 표현을 먼저 다듬고 자연스러운 한국어를 별도 검수한다.

## 정보 구조

문서와 내용을 독립적으로 이해해야 하는 주요 섹션은 결론을 먼저 제시한다.
한 문단에는 하나의 주장만 담고 보통 2~4문장으로 근거와 의미를 설명한다.
한 문장짜리 결론이나 5문장 이상의 상세 설명도 의미를 인위적으로 합치거나 나누지 않는 편이 읽기 쉬우면 허용한다.
제목은 내용을 예측할 수 있는 구체적인 명사구로 쓰며 제목만 훑어도 문서 흐름이 드러나야 한다.

문단이 세 개 이상 이어지고 중간에 독립된 주제가 나타나면 소제목 분리를 검토한다.
목록은 병렬 항목에 사용하고 표는 같은 필드의 비교에만 사용한다.
굵은 글씨와 콜아웃은 결정·경고처럼 놓치면 안 되는 정보에만 쓴다.

## 줄바꿈과 문단

Markdown 소스에서는 완결된 문장마다 줄을 바꾼다.
문장 중간을 임의의 글자 수로 자르지 않는다.
같은 의미 단락의 문장은 연속된 줄에 두고 주장이나 화제가 바뀔 때만 빈 줄을 넣는다.
한 문장마다 빈 줄을 넣어 글을 조각내지 않는다.

코드 블록, 표, 목록, 인용문은 앞뒤에 빈 줄을 둔다. 문서 형식이나 대상 저장소의 포매터가 별도 줄바꿈 규칙을 강제하면 그 규칙을 우선한다.

## 자연스러운 한국어

문법 정확성을 기본으로 삼고 한국인이 실제로 자연스럽게 읽는 문장을 목표로 한다.
주어와 서술어의 호응, 수식어와 피수식어의 거리, 조사, 시제, 높임의 일관성을 확인한다.
영어식 명사 나열과 긴 명사구는 동사가 살아 있는 문장으로 풀고 불필요한 한자어와 추상 명사를 구체적인 표현으로 바꾼다.

같은 개념에는 같은 용어를 쓴다. 기술 용어는 처음 나올 때만 짧게 정의하고 이후에는 정한 용어를 유지한다. 정확한 수치, 단위, 경로, 명령, 코드, 오류 문자열은 문체를 다듬더라도 바꾸지 않는다.

## 화살표

화살표는 짧은 선형 관계를 문장보다 빨리 읽을 수 있을 때만 쓴다. 인과, 상태 전이, 입력·처리·출력처럼 관계가 하나인 흐름을 최대 3~4단계로 표현한다.

```text
캐시 만료 → 동시 요청 폭주 → DB 커넥션 고갈
```

일반 산문 안에서는 화살표를 쓰지 않는다. 분기, 예외, 반복, 단계별 설명이 필요하면 번호 목록, 표, Mermaid 다이어그램을 사용한다. 화살표만 읽어도 각 항목의 주어와 관계가 분명해야 한다.

## 검수

첫 번째 독자 검수는 체크리스트 없이 문서를 읽고 정보 순서, 제목, 문단 경계, 줄바꿈, 훑어보기 쉬운 정도를 평가한다.
첫 화면과 제목만 보고 목적·결론을 찾고 다음 행동이 명시된 문서는 그것까지 찾을 수 있는지 확인한다.
길거나 막히는 문단, 서로 다른 주제를 섞은 문단, 부적절한 목록·표·화살표를 찾는다.
각 발견 사항은 위치, 독자가 겪는 문제, 최소 수정안 순서로 기록하고 심각도 순으로 정렬한다.

두 번째 한국어 편집은 자연스러운 어순과 호응을 먼저 보고 기존 번역투·맞춤법 체크리스트를 안전망으로 적용한다.
기계적으로 금지 표현만 치환하지 않는다.
두 검수는 기존처럼 별도 컨텍스트에서 실행한다.
변경률은 코드 블록·명령·인용을 제외한 비어 있지 않은 산문 줄 가운데 수정할 줄의 비율로 계산한다.
변경률이 30%를 넘으면 문서를 수정하지 않고 발견 사항과 계산 근거를 보고한다.

## 변경 범위와 검증

`skills/korean-docs/SKILL.md`에 위 계약을 넣는다.
같은 동작을 설명하는 `README.md`, `CONTRIBUTING.md`, `hooks/korean-writing-reminder.js`, `docs/test-scenarios.md`를 함께 맞춘다.
`.claude-plugin/plugin.json`의 `version`과 `.claude-plugin/marketplace.json`의 `metadata.version`, ruccess 플러그인 `version`을 동일하게 올린다.

RED와 GREEN은 같은 Markdown 입력을 사용한다.
입력은 장애 원인과 배포 계획을 한 문단에 섞고, 문장을 한 줄에 몰아 쓰며, 자연스럽지 않은 명사 나열과 단순 인과 관계를 포함한다.
RED에서는 현재 스킬이 문장별 소스 줄바꿈, 의미 단락 분리, 제한된 화살표 사용 가운데 하나 이상을 누락하는지 기록한다.
GREEN에서는 서로 다른 두 주제를 빈 줄과 제목으로 분리하고, 같은 문단의 완결 문장마다 소스 줄을 바꾸며, 자연스러운 한국어 수정안을 제시해야 한다.
세 단계 이내의 단순 인과는 화살표 후보로 제안하고 분기·예외가 섞인 관계는 화살표로 축약하지 않아야 한다.
대상 저장소의 포매터가 줄바꿈을 강제하면 그 규칙을 따르고 예외 근거를 기록한다.

검증은 `node scripts/validate.mjs`, `quick_validate.py skills/korean-docs`, `git diff --check`로 수행한다.
저장소 검증기는 종료 코드 0과 `ok: validated 9 skills and 2 manifests`, 스킬 검증기는 종료 코드 0과 `Skill is valid!`, diff 검사는 출력 없음이 성공 기준이다.
