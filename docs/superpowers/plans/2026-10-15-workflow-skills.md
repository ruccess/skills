# 개발 스킬의 판단 기준과 협업 방식 개선

기존 개발 스킬 이름을 유지하면서 맷 포콕 스킬의 작업 분해, 테스트 판단, 리뷰 분리, PR 증거 제시 방식을 선별해 적용한다.
사용자는 2026-10-15 대화에서 이 방향의 작업 진행을 승인했다.
원본 이름이나 전체 구성을 따라가는 변경은 범위에서 제외한다.

## 요구사항과 검증

정본은 이 작업의 사용자 대화이며 별도 버전 번호는 없다.
아래 표는 2026-10-15 구현 합의와 2026-10-16 전달 요청을 반영한 사본이다.

| 요구사항 | 변경 대상 | 검증 방법 |
| --- | --- | --- |
| 기존 개발 스킬 이름 유지 | 기존 SKILL.md | 기존 이름과 호출 경로 보존 확인 |
| 독립적으로 검증할 수 있는 기능 단위와 의존관계 | dev-plan | 각 단계의 동작·검증·선행 조건을 사례로 평가 |
| 외부 동작을 검증하는 테스트 기준과 작은 구현 반복 | dev-build | 명확한 버그 수정, 잘못된 테스트, 문서 변경 사례 평가 |
| 규칙 준수와 요구사항 충족을 구분한 리뷰 | dev-ship | 규칙은 맞지만 요구사항이 빠진 사례 평가 |
| 전후 증거와 영향 중심의 PR 및 간결한 보고 | dev-ship | 작은 수정의 보고와 미검증 결과 구분 평가 |
| 질문 중복과 불필요한 재승인 제거 | brainstorm, dev-plan, grill | 이미 합의된 결정 재질문 여부 평가 |
| 함께 학습·고민·결정하는 범용 동료 역할 분리 | thinker | 기술·업무·학습 사례에서 설명·공동 탐구·잠정 결론 평가 |
| 저장소 규칙·원문 요구·무관한 변경 보존 | 개발 스킬과 문서 | 기존 거버넌스·검증 실패 시나리오와 diff 검토 |
| 문서·평가·배포 메타데이터 일관성 | README, CONTRIBUTING, evals, manifests | 검증 스크립트와 평가 도구 회귀 검사 |
| 작업 단위별 커밋·푸시·Draft PR | 작업 브랜치와 PR | 커밋별 diff, 원격 브랜치, Draft 여부와 기준 브랜치 확인 |

## 구현 순서

1. 기존 스킬을 적용한 고정 사례와 스킬 없는 기준선을 별도 평가 맥락에서 실행해 실제 응답을 남긴다.
2. dev-plan과 dev-build에 작업 분해·검증 기준을 반영하고, brainstorm과 grill의 책임 경계를 정리한다.
3. dev-ship에서 변경 위험에 맞는 검토, 두 관점의 리뷰, 전후 증거 중심의 PR과 보고를 정리한다.
4. 사용자 답변으로 별도 동료 스킬의 범위를 확정하고, 이해 공유·공동 탐색·잠정 결론을 다루는 지침을 작성한다.
5. 문서와 평가 기준을 갱신하고, 같은 사례의 개선 후 응답과 안전장치 회귀를 확인한다.

2번과 3번은 1번의 해당 기준선 확보 후 독립적으로 진행할 수 있다.
4번은 적용 범위 답변을 기다리되 기존 개발 스킬 개선을 막지 않는다.
5번은 스킬 내용이 확정된 뒤 수행한다.

## 검증과 한계

`node scripts/validate.mjs`, `node --test evals/run.test.mjs evals/score.test.mjs`, `git diff --check`를 실행한다.
행동 평가는 고정 사례와 동일한 모델·추론 설정을 사용하고 실제 응답과 판정 이유를 기록한다.
소수의 모의 사례는 실제 저장소 작업 전체의 성능이나 비용 개선을 입증하지 못한다.
검증 실패, 미충족 거버넌스, 근거 없는 요구사항 제외는 간소화 대상이 아니다.

## 작업 공간과 합의된 범위

다른 작업의 변경을 보존하기 위해 `feature/workflow-skill-improvements` 브랜치의 별도 워크트리에서 진행한다.
원래 작업 폴더의 한국어 스킬·문서·훅·메타데이터 변경은 이 작업에 포함하지 않는다.
병행 작업이 완료된 뒤 기준 커밋을 `6aecb3c`로 갱신했고, 해당 변경을 보존한 상태에서 이 작업의 차이만 남겼다.
사용자는 개발 외 업무·학습을 포함하는 범용 동료 역할을 선택했으며 이름으로 `thinker`를 제안했다.
사용자는 2026-10-16 작업 단위별 커밋·푸시·Draft PR 생성을 요청했다.
기존 한국어 개선의 PR #1이 `main`에 병합된 것을 확인했으므로 `main`을 기준으로 이번 변경만 제출한다.
