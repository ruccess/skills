# 외부 리뷰 후속 수정과 블라인드 행동 평가

2026-11-19에 스킬 스위트 전체를 외부 관점으로 리뷰하고, 지적된 항목을 고친 뒤 행동 평가를 다시 실행했다.
평가는 사례마다 조건별 1회만 실행했으므로 방향 확인용이며 통계적 근거가 아니다.
자동 A/B 러너(`run.mjs`)와 새 행동 평가 러너(`behavior.mjs`)는 실제 모델로 돌리지 못했고, 그 이유와 남은 실행은 마지막 절에 적는다.

## 리뷰가 지적한 것과 고친 것

| 지적 | 조치 |
| --- | --- |
| 평가 러너가 저장소 안에서 돌고 운영자의 `gh` 자격을 그대로 쓴다 | 작업 폴더를 저장소 밖 임시 폴더로 옮기고, 실행마다 git을 초기화하며, `gh` 자격을 격리했다 |
| 리뷰 서브에이전트 탐지가 옛 도구 이름 `Task`만 본다 | `Agent`와 `Task`를 모두 인정하고 양성·음성 회귀 테스트를 추가했다 |
| 한국어 행동 평가의 사례가 스킬 본문 예시와 같고, 생성자가 판정 기준을 받았다 | 예시와 겹치지 않는 `korean-heldout-cases.json`을 추가하고, 생성자와 판정자를 분리한 `behavior.mjs`를 만들었다 |
| `korean-chat`은 채팅 응답에서 발동할 장치가 없다 | 프롬프트에 한글이 있으면 세션당 한 번 상기시키는 `UserPromptSubmit` hook을 추가했다 |
| 문서 리마인드 hook이 코드 파일의 한국어에도 발동한다 | 문서 확장자에만 발동하게 했다 |
| `dev-build`의 테스트 우선에 "쓸 만한 접점이 없으면"이라는 우회로가 있다 | 실행해 관찰할 인터페이스가 없는 변경으로 한정하고, 건너뛸 때는 없는 접점을 밝히게 했다 |
| `brainstorm`의 게이트가 "중요한"이라는 판단어에만 기댄다 | 중요한 선택을 정의하고 `thinker`와의 경계를 양쪽 스킬에 적었다 |
| `korean-docs`가 변경 규모와 무관하게 서브에이전트 두 개를 요구한다 | 쓰거나 바꾼 산문이 30줄 미만이면 두 pass를 인라인으로 수행하게 했다 |
| 출처 표기가 빠졌거나 낡았다 | `grill`의 원본을 밝히고 `THIRD_PARTY_NOTICES.md`에 나머지 출처를 정리했다 |
| 문서와 스킬 본문이 어긋난다 | README, CONTRIBUTING, 검증 시나리오, 기록용 설계 문서를 현재 본문에 맞췄다 |

`dev-ship`의 리뷰 깊이와 심각도 기준, batching 병렬도 집계, caveman 라이선스 표기는 [2026-11-18 기록](findings-2026-11-18-review-severity.md)에서 이미 고쳤다.

## 평가 방법

응답 생성과 판정은 모두 이 작업 세션의 Claude Sonnet 서브에이전트가 했다.
생성자는 사례의 요청과 상황만 받았고, 스킬 조건에서는 해당 `SKILL.md` 한 파일을 읽었다.
판정 기준은 생성자에게 주지 않았다.
판정자는 사례마다 하나이며, 그 사례의 모든 조건 응답을 순서를 섞은 `R1..Rn`으로 받았고 어느 응답이 어느 조건인지 알지 못했다.
조건은 스킬 없음(none), 변경 전 스킬(old, 커밋 `dc2f432`), 변경 후 스킬(new)이다.
한국어 사례는 none과 new만 실행했다.

이 방식에는 한계가 두 가지 있다.
첫째, 서브에이전트는 운영자의 전역·프로젝트 지침 파일과 스킬 목록을 그대로 물려받는다.
전역 지침에는 한국어 응답 규칙과 테스트 우선 규칙이 들어 있으므로 none 조건은 깨끗한 무스킬 기준선이 아니다.
둘째, 한 판정자가 같은 사례의 여러 응답을 나란히 보므로 응답끼리 비교해 점수를 매겼을 수 있다.
응답 원문과 기준별 판정 이유는 [`behavior-results-2026-11-19.json`](behavior-results-2026-11-19.json)에 있다.

## 결과

### 한국어 스킬

| 사례 | 스킬 | none | new |
| --- | --- | --- | --- |
| chat-beginner-webhook | korean-chat | 5/5 | 5/5 |
| chat-status-migration | korean-chat | 4/4 | 4/4 |
| chat-requested-register-timeout | korean-chat | 3/4 | 4/4 |
| chat-comparison-session-store | korean-chat | 4/5 | 5/5 |
| docs-beginner-coupon | korean-docs | 4/6 | 6/6 |
| docs-fidelity-index | korean-docs | 5/5 | 5/5 |
| 합계 | | 25/29 | 29/29 |

none 조건이 놓친 기준은 네 개다.

- 명사형 공유 메시지에 주어지지 않은 결과("기존 3초로는 정상 응답도 타임아웃 처리됨")를 덧붙였다.
- 비교 응답 끝에서 새 정보 없이 결론을 반복했다.
- 문서 설명에서 "원자적 차감"을 쉬운 말로 풀지 않고 주어진 문장을 되풀이했다.
- 말투 요청이 없는 문서를 합니다체로 썼다.

스킬 조건은 네 기준을 모두 충족했다.
나머지 25개 기준은 none 조건도 충족했으므로 개선 효과로 집계하지 않는다.
2026-10-15 평가에서는 기준선이 19개를 모두 통과해 차이가 없었는데, 이번에는 스킬 본문 예시와 다른 사례에서 네 기준이 갈렸다.

### 개발 스킬

| 사례 | 스킬 | none | old | new |
| --- | --- | --- | --- | --- |
| build-test-first-in-untested-module | dev-build | 4/4 | 4/4 | 4/4 |
| brainstorm-skip-design-pressure | brainstorm | 1/4 | 4/4 | 3/4 |
| brainstorm-concrete-change-not-gated | brainstorm | 3/4 | 3/4 | 4/4 |
| 합계 | | 8/12 | 11/12 | 11/12 |

`dev-build` 사례는 세 조건이 모두 통과해 지표가 갈리지 않았다.
운영자의 전역 지침에 테스트 우선 규칙이 있어 none 조건도 실패하는 테스트부터 계획했다.
따라서 이 사례는 테스트 우선 문구를 고친 효과를 보여 주지 못한다.

`brainstorm`의 압박 사례에서 none 조건은 질문 여섯 개를 한꺼번에 늘어놓고 발송 수단 같은 구현 세부를 물었다.
변경 전 스킬은 네 기준을 모두 충족했다.
변경 후 스킬은 질문을 하나로 좁혔지만 후속 확인 목록에 "이메일 발송 수단"을 넣어 구현 세부를 묻지 않는다는 기준을 놓쳤다.
이 결과를 보고 `brainstorm` 3단계에 "방식이 아니라 사용자가 관찰할 결과를 묻는다"는 문장을 추가했다.
같은 사례를 다시 실행하자 구현 세부 기준은 충족했지만, 이번에는 한 번에 두 가지를 묻고 후속 질문을 미리 나열해 질문 하나 기준을 놓쳤다.
재실행 응답은 다른 조건과 나란히 놓지 않고 단독으로 판정했다.
두 번 모두 3/4이므로 이 사례에서는 변경 후 스킬이 변경 전보다 낫다는 근거가 없다.

대조 사례인 구체적 변경에서는 none과 변경 전 스킬이 "진행하라고 하시면 수정하겠습니다"라며 승인을 기다렸다.
변경 후 스킬은 재승인 없이 진행 계획을 제시했다.
이는 중요한 선택이 아니면 결정하고 계속한다는 문장을 넣은 방향과 일치하지만 1회 관측이다.

## 실행하지 못한 것

자동 A/B 러너와 `behavior.mjs`는 `claude -p`를 호출한다.
평가를 실행한 PC의 `claude` CLI는 로그인돼 있지 않았다(`claude auth status`가 `loggedIn: false`를 반환했다).
그래서 다음 세 가지는 확인하지 못했다.

- 현재 판 스킬로 실행한 `ship-fastpath-abuse`·`ship-governance`·`ship-gates`·`batching` 과제의 결과
- 플러그인으로 설치했을 때의 자연 발동률(`behavior.mjs`의 plugin arm)과 새 `UserPromptSubmit` hook이 `korean-chat` 호출로 이어지는 비율
- 깨끗한 무스킬 기준선과의 비교

두 러너의 격리·채점 로직은 가짜 `claude`를 쓰는 회귀 테스트 36개로 검증했고, hook 두 개는 테스트 4개로 검증했다.
CLI에 로그인한 환경에서는 다음 명령으로 남은 실행을 할 수 있다.

```bash
node evals/run.mjs --tasks ship-fastpath-abuse,ship-governance,ship-gates,batching --reps 2 --max-turns 60
node evals/score.mjs evals/results/<run-id>
node evals/behavior.mjs --cases evals/korean-heldout-cases.json
node evals/behavior.mjs --cases evals/workflow-quality-cases.json --arms none,skill
```

## 이전 기록의 정정

2026-08-10 기록의 "batching 병렬도 1.00 동률"은 기록 항목 단위로 센 값이다.
로컬 전사 다섯 개를 다시 세면 항목 단위는 모두 1.00이고 모델 응답(`message.id`) 단위는 1.27~2.50이었다.
당시 결과는 다시 채점하지 않았으므로 스킬 효과 판단에 쓰지 않는다.

2026-10-15 한국어 평가의 최종 21개 항목 통과는 생성자가 판정 기준을 받은 상태에서 나온 결과다.
사례 두 개는 스킬 본문 예시와 같은 요청이었다.
그 결과는 말투 회귀 확인으로만 읽고 스킬의 일반적인 효과로 읽지 않는다.
