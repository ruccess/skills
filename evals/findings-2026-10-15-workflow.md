# 개발 스킬과 thinker 행동 평가

기존 스킬 이름을 유지하며 절차 과잉을 줄인 변경과, 함께 학습·탐구하는 `thinker`의 역할을 모의 사례로 확인했다.
평가일은 2026-10-15이며 비교한 기준 파일은 커밋 `45374e351e6b09d8f0aa8fb3c2efb6aedf38cefd`의 개발 스킬이다.
이 결과는 실제 코드 수정·PR 생성·CI·배포 성공을 뜻하지 않는다.

## 평가 조건

행동 응답은 `gpt-5.6-sol`, 추론 `medium`으로 생성했다.
평가 에이전트에는 고정 요청과 모의 상황을 전달했고, 스킬 조건에만 해당 SKILL.md를 읽도록 했다.
판정 기준은 [`workflow-quality-cases.json`](workflow-quality-cases.json)에 두고 응답 생성 에이전트에는 전달하지 않았다.
실제 응답을 받은 뒤 주 작업 맥락에서 항목별 근거를 대조했다.
아래 인용은 실제 응답의 발췌다.

기존 스킬과 개선 후 스킬은 사례마다 새 에이전트 맥락을 사용했다.
스킬 없는 대조군의 build·ship 두 사례만 같은 에이전트 맥락을 사용했으므로 완전히 독립된 대조군은 아니다.
기존 스킬 두 사례와 개선 후 같은 두 사례는 각각 동일한 요청·모의 상황·출력 상한으로 비교했다.
원래 사용자 지침을 강제해 실패하게 만든 상황이 아니라, 합의된 작업과 간결한 보고 요청에 기존 지침을 적용한 응답을 비교했다.

## 관측한 실패와 수정

### 명확한 합의와 계획 파일

스킬 없는 대조군은 별도 계획 파일 없이 수정하겠다고 답했다.
기존 `dev-build`는 사용자 요청과 저장소 규칙이 계획 파일을 요구하지 않는데도 다음과 같이 중단했다.

> 현재 합의 내용은 명확하지만, dev-build 절차는 별도의 계획 문서가 없으면 구현을 시작할 수 없도록 규정합니다.

개선 후에는 합의대로 진행하며 공개 함수 회귀 테스트의 실패를 먼저 확인하는 순서를 제시했다.

> 별도 계획 파일은 만들지 않겠습니다. … calculateTotal(cart)을 직접 호출하는 0% 할인 회귀 테스트를 추가하고 예상한 이유로 실패하는지 확인하겠습니다.

수정 후 응답은 독립적인 기대 금액, 최소 수정, 양수 할인율 보존, 대상 테스트와 타입 검사를 포함했다.
실행하지 않은 테스트를 통과했다고 표현하지 않았다.

### 간결한 출고 보고

스킬 없는 대조군은 변경 동작·검증·남은 문제를 간결히 보고했다.
기존 `dev-ship`은 같은 요청에 변경 규모와 1~8 단계 상태표를 추가했다.
개선 후에는 상태표 없이 Draft URL, `-`에서 `0원`으로 바뀐 동작, `npm test` 12/12와 린트 결과를 제시했다.
PR 본문에는 되돌리면 기존 표시로 복귀한다는 영향을 적고, 원격 CI와 배포는 미확인으로 구분했다.

### 기능 단위 계획의 중간 실패

첫 개선판은 작은 기능 단위를 지시했지만 평가 응답이 상태 API·발송 처리·로그·화면·통합 검증으로 분리됐다.
각 단계에 테스트가 있어도 요청한 동작이 여러 단계 이후에야 완성되는 문제가 남았다.
이를 근거로 `dev-plan`에 즐겨찾기 추가·제거의 화면·저장·리로드 경로 예시와 계층별 분해의 반례를 추가했다.
평가 요청은 별개의 알림 중지·재개 기능으로 유지했다.

새 맥락에서 재평가한 응답은 알림 중지와 재개를 각각 운영 화면·상태 저장·발송 대상 조회·감사 로그가 연결된 단위로 구성했다.
화면의 이력 표현 완성은 별도 사용자 관찰 결과로 남겼으며, 스키마 질문은 사용자에게 요구를 다시 묻지 않고 코드 조사 항목으로 두었다.

최종 기술·업무·잠정 결론·합의된 실행 사례는 이 예시 변경 후 각각 새 맥락에서 다시 확인했다.
이 사례들에 대한 스킬 없는 대조군은 실행하지 않았으므로 `thinker`가 일반 모델보다 우수하다는 비교 결론은 내리지 않는다.

## 평가 도구와 검증 범위

평가기는 모든 PR 시도가 Draft인지 판정하도록 보완하고, 파일 수 보고와 fast path 선언을 품질 집계에서 제외했다.
과거 원시 필드와 상세 진단은 유지한다.
복합 셸 구문과 본문 속 플래그를 Draft 증거로 오인하는 사례도 별도 회귀 검사로 확인한다.
2026-10-16 출고 점검에서는 상충하는 Draft 옵션, 문자열 옵션 값으로 쓰인 플래그, 미지원 옵션도 미확인으로 처리하는 회귀 사례를 추가했다.
`node scripts/validate.mjs`는 스킬 10개와 매니페스트 2개를 검증했다.
병행 작업의 최신 커밋 `6aecb3c`를 기준으로 변경을 다시 적용한 뒤 `node --max-old-space-size=256 --test --test-concurrency=1 evals/run.test.mjs evals/score.test.mjs`를 실행해 20개 통과, 실패 0개를 확인했다.
이 과정에서 미완료 평가 결과의 채점 차단과 한국어 스킬 변경을 보존했고, 평가한 개발 스킬 내용이 재적용 전과 같은지도 확인했다.
행동 사례 JSON의 8개 식별자 중복·필수 필드 검사와 `git diff --check`도 통과했다.

이 평가는 소수의 고정 사례이며 판정자는 주 작업 에이전트다.
모델의 변동성, 실제 도구 실행, 자동 스킬 선택, 장기 대화에서의 행동 유지, 전체 프로젝트의 회귀 안전성을 입증하지 못한다.
검증 실패·거버넌스 미충족의 실제 저장소 A/B 과제는 이번 작업에서 새로 실행하지 않았다.
기존 자동 과제와 회귀 테스트는 남겨 두었으며, 새 사례는 수동 행동 평가로 구분한다.
