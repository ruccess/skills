# A/B 평가 파일럿 결과 — 2026-08-10

## 결론

스킬 스위트는 헤드리스 실행에서 실제로 발견되고 호출되며, 출하 게이트 행동을 계측 가능하게 바꾼다. 대가는 과제당 비용 +26~43%와 캐시 읽기 약 +95K 토큰이다. 한국어 산문 지표는 sonnet의 기본 품질이 이미 높아 이 방식으로는 갈리지 않았다.

실험은 두 라운드로 진행했다. 1차(12실행)에서 과제 설계 결함 두 건을 발견해 고쳤고, 2차(8실행)에서 수정된 과제를 재실행했다. 실행은 총 20회고 실비용은 약 $4.9다(모델 sonnet, 팔당 반복 2회).

## 방법 요약

- 처치군(A): `claude -p --setting-sources project,local --plugin-dir <ruccess/skills>`
- 대조군(B): 같은 명령에서 `--plugin-dir`만 제거
- 두 팔 모두 사용자 설정(다른 플러그인·hook·전역 CLAUDE.md)을 배제한다. 두 팔의 차이는 정확히 플러그인 하나다
- 채점은 트랜스크립트 기반 이진·수치 지표다. 세부는 `evals/README.md` 참조

## 지표별 결과

### ship-gates — 갈렸다 (2차, 수정된 픽스처)

main 대비 1커밋 diff, 실패하는 테스트 1개, push 가능한 로컬 origin이 있는 픽스처에 "PR 올려라"를 주었다.

| 지표 | ARM A | ARM B |
|---|---|---|
| dev-ship 호출 | 2/2 | 0/2 |
| PR 전 테스트 실행 | **2/2** | **0/2** |
| PR 생성 시도 없음 | 2/2 | 2/2 |

두 팔 다 PR을 만들지 않았지만 이유가 다르다. A는 `node --test`를 돌려 실패를 발견하고 검증 게이트에서 멈췄다. B는 테스트를 한 번도 실행하지 않은 채 `gh repo view`·`gh auth status` 등 원격 진단에 턴을 쓰다 도구 장벽에 막혀 멈췄다. gh가 정상 동작하는 환경이었다면 B는 실패하는 테스트를 모른 채 PR을 만들었을 개연성이 높다 — 단 이것은 관측이 아니라 추정이다.

### korean-readme — 플로어 효과, 신호 없음 (1·2차 동일)

번역투 위반 30건으로 오염한 spec.md를 주고 README 작성을 시켰다. 두 팔 모두 위반 0 — sonnet은 대조군에서도 원문을 베끼지 않고 깨끗하게 재작성했다. korean-docs는 A팔에서 2/2 호출됐지만 이 지표로는 가치를 증명할 수 없다. 이 스킬의 효용은 생성이 아니라 기존 문서 검수에서 나온다(내장 체크리스트 단독으로 심어둔 위반 8/8 검출 — `docs/test-scenarios.md`의 GREEN 기록). 생성 과제로 가르려면 더 약한 모델이나 훨씬 긴 문서가 필요하다.

### batching — 병렬도 동률, 총 호출 수만 차이 (1차)

병렬도(메시지당 tool_use)는 두 팔 모두 1.00으로 갈리지 않았다. 총 툴 호출은 A 3~4회, B 10~11회로 A가 적었지만 겨냥한 context-thrift가 발동한 결과가 아니다.

### 토큰·비용 오버헤드 (전 과제)

| 지표 | ARM A | ARM B | 차이 |
|---|---|---|---|
| 실행당 비용 평균 (1차) | $0.253 | $0.177 | +43% |
| 실행당 비용 평균 (2차) | $0.306 | $0.243 | +26% |

스킬 본문을 읽고 절차를 밟는 비용이다. 짧은 과제일수록 비중이 크고, 게이트가 실제로 사고를 막는 과제에서는 이 오버헤드가 보험료 성격이 된다.

## 스위트 자체의 발견 사항

1. **context-thrift가 헤드리스에서 발동하지 않는다 (0/2).** description "Use in any agent session where token cost matters"는 모델이 자기 상황으로 인식하지 못하는 트리거다. description 재작성이 필요하다 — 스킬 TDD 절차를 거쳐 후속 버전에서 처리할 것.
2. 스킬 발견율 자체는 높다 — 관련 과제에서 korean-docs 4/4, dev-ship 4/4.
